# 性能基线（Performance Baseline）

本文件记录 MVP 2 研究回测引擎在**目标规模**下的运行时间与内存基线（SP 2.84）。
基线由 `tests/test_performance_baseline.py` 测量并守护：回测以固定 Mock 数据在
目标规模运行一次，将实测运行时间与峰值内存与本文记录的值对比；超出宽松上限
即视为性能回归。

> 基线数值依赖运行机器的 CPU、内存与负载，仅作研究参考，不构成性能承诺。

## 目标规模

- **市场**：单一市场（US，用于 252 交易日/年）
- **标的数量**：20 只
- **时间跨度**：5 年（2019-01-01 → 2023-12-31）
- **交易日**：约 1304 个（工作日，无节假日近似）
- **调仓频率**：季度（20 个季度首日顺延后的调仓日）
- **日线数据量**：20 × 1304 ≈ 26,080 条 OHLCV

## 测量方式

- **运行时间**：`time.perf_counter()` 包住 `run_end_to_end_backtest` 单次执行。
- **内存**：`tracemalloc` 记录单次执行期间的峰值已追踪内存（Python 堆分配）。
- 固定 Mock 数据、固定配置、固定随机种子（引擎本身无随机性），结果可重放。

## 实测基线（2026-08-08，开发容器，Python 3.12.3）

| 指标 | 实测值 |
| :--- | :---: |
| 运行时间 | ≈ 1.9 s |
| 峰值内存（tracemalloc） | ≈ 6.2 MiB |
| 日线数量 | 1304 |
| 每日对账失败 | 0 |

## 守护上限（测试断言）

| 指标 | 上限 | 说明 |
| :--- | :---: | :--- |
| 运行时间 | 30 s | 实测 ~15 倍余量，避免慢机器/负载波动导致的误报 |
| 峰值内存 | 512 MiB | 实测 ~80 倍余量，仅拦截灾难性内存回归 |

上限以 `_RUNTIME_CEILING_SECONDS` / `_MEMORY_CEILING_BYTES` 常量形式固化在
`tests/test_performance_baseline.py`，与本文保持一致（防漂移）。

## 说明

- 引擎为低频、纯 Python 回测（SP 2.47 逐日流水线：信号 → 调仓 → 成交 → 企业行动
  → 估值 → 持久化）；目标规模单次运行在秒级完成。
- 性能基线只用于**发现严重回归**，不作为吞吐量的绝对承诺；进入 MVP 3 后如需更高
  吞吐量，再引入向量化（如 VectorBT）或并行化，并重新校准本文基线。

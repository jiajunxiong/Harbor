# 性能基线（Performance Baseline）

本文件记录 MVP 2 研究回测引擎在**目标规模**下的运行时间与内存基线（SP 2.84）。
基线由 `tests/test_performance_baseline.py` 测量并守护：回测以固定 Mock 数据在
目标规模运行一次，将实测运行时间与峰值内存与本文记录的值对比；超出宽松上限
即视为性能回归。

> 基线数值依赖运行机器的 CPU、内存与负载，仅作研究参考，不构成性能承诺。

## 目标规模

- **市场**：单一市场（US，用于 252 交易日/年）
- **标的数量**：20 只
- **时间跨度**：5 年（2019-01-01 → 2023-12-31）
- **交易日**：约 1304 个（工作日，无节假日近似）
- **调仓频率**：季度（20 个季度首日顺延后的调仓日）
- **日线数据量**：20 × 1304 ≈ 26,080 条 OHLCV

## 测量方式

- **运行时间**：`time.perf_counter()` 包住 `run_end_to_end_backtest` 单次执行。
- **内存**：`tracemalloc` 记录单次执行期间的峰值已追踪内存（Python 堆分配）。
- 固定 Mock 数据、固定配置、固定随机种子（引擎本身无随机性），结果可重放。

## 实测基线（2026-08-08，开发容器，Python 3.12.3）

| 指标 | 实测值 |
| :--- | :---: |
| 运行时间 | ≈ 1.9 s |
| 峰值内存（tracemalloc） | ≈ 6.2 MiB |
| 日线数量 | 1304 |
| 每日对账失败 | 0 |

## 守护上限（测试断言）

| 指标 | 上限 | 说明 |
| :--- | :---: | :--- |
| 运行时间 | 30 s | 实测 ~15 倍余量，避免慢机器/负载波动导致的误报 |
| 峰值内存 | 512 MiB | 实测 ~80 倍余量，仅拦截灾难性内存回归 |

上限以 `_RUNTIME_CEILING_SECONDS` / `_MEMORY_CEILING_BYTES` 常量形式固化在
`tests/test_performance_baseline.py`，与本文保持一致（防漂移）。

## 说明

- 引擎为低频、纯 Python 回测（SP 2.47 逐日流水线：信号 → 调仓 → 成交 → 企业行动
  → 估值 → 持久化）；目标规模单次运行在秒级完成。
- 性能基线只用于**发现严重回归**，不作为吞吐量的绝对承诺；进入 MVP 3 后如需更高
  吞吐量，再引入向量化（如 VectorBT）或并行化，并重新校准本文基线。

## MVP 3：验证性能基线（SP 3.83）

MVP 3 样本外验证管线的性能基线由 `tests/test_validation_performance_baseline.py`
测量并守护，覆盖三项关键操作的目标规模运行时间与峰值内存（性能基线）。

### 目标规模

- **清单构建**：1 市场（HK）、**9 个数据组件**（SP 3.6 ManifestComponent）、
  2019-01-01 → 2024-12-31（2192 天窗口），构建并生成自洽的 SP 3.7 数据指纹。
- **参数预算**：3 参数空间（SP 3.15）、**100 次试验**在 `max_trials=100` 的声明预算
  内注册（SP 3.17/3.18），每次试验参数与指标各不相同。
- **滚动回测**：**10 折**滚动 OOS 流水线（SP 3.33 训练 → 3.34 验证 → 3.35 OOS →
  3.37 拼接），测试期 2023-01-01 → 2026-12-30，`step_days=146`。

### 测量方式

- 每个操作在 `time.perf_counter()` + `tracemalloc` 下各执行一次（tracemalloc 在每
  次操作前重启以记录该操作的峰值），固定 Mock 数据、固定配置、固定种子，结果可重放。
- 基线数值依赖运行机器的 CPU、内存与负载，仅作研究参考，不构成性能承诺。

### 守护上限（测试断言）

| 操作 | 运行时间上限 | 峰值内存上限 | 说明 |
| :--- | :---: | :---: | :--- |
| 清单构建 | 5 s | 128 MiB | 纯内存模型构建 + 指纹，实测远低于上限 |
| 参数预算 | 10 s | 256 MiB | 100 次登记 + 校验 + 指纹 |
| 滚动回测 | 30 s | 512 MiB | 10 折纯 Python 滚动流水线 |

上限以 `_MANIFEST_RUNTIME_CEILING` / `_BUDGET_RUNTIME_CEILING` /
`_ROLLING_RUNTIME_CEILING`（及对应 `*_MEMORY_CEILING`）常量固化在
`tests/test_validation_performance_baseline.py`，与本文保持一致（防漂移）。

> 与 MVP 2 回测性能基线（SP 2.84，本文件上半部分）配套：两者都只用于发现严重
> 性能回归，不作为吞吐量承诺。
